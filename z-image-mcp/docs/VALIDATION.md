# 验证记录

验证日期：2026-09-08。服务版本：0.1.0。

## 环境

- GPU：NVIDIA RTX PRO 6000 Blackwell Workstation Edition，96 GB 显存。
- 驱动：595.84；PyTorch 2.13.0 + CUDA 13.0。
- Diffusers 0.39.0、Transformers 5.15.1、Accelerate 1.14.0、MCP SDK 1.30.0。
- 服务端：Linux，独立 Python 3.14.6 venv；测试客户端：Python 3.13.13。
- 模型：本地 `Tongyi-MAI/Z-Image-Turbo` 完整 Diffusers 快照；BF16，直接加载到 CUDA。
- 使用 PyTorch 默认 SDPA；没有启用 torch.compile、量化或 Flash Attention 扩展。

## 代码与协议

- 本地和服务器分别通过 **19 项测试**。
- Ruff、Shell 语法检查通过；可编辑包安装和命令入口通过。
- 服务器 `pip check` 无依赖冲突；systemd unit 校验通过。
- 真正的 HTTP MCP 握手、6 个工具的发现、标准进度通知、结构化结果和图片内容已验证。
- 自动化覆盖参数/像素/队列/磁盘限制、串行执行、失败恢复、排队/运行取消、
  重启记录、单进程锁、Bearer 令牌、Host 校验和下载完整性。
- 生成工具的在线参数 Schema 仅包含 `prompt`、`width`、`height`，其中只有 `prompt` 必填。
  自动化验证直接生成和后台提交都由服务端分配随机种子、固定使用 9 步。

## 真实 GPU 测试

由独立客户端通过部署的 MCP HTTP 端点调用，实际下载 PNG 并验证格式、尺寸、SHA-256。
中文橘猫和英文小熊猫提示词输出已人工查看，内容符合提示词。
下表保留首次部署时的实测记录；当前客户端不再传入 `seed`、`steps`。

| 测试 | 输出 | 模型加载 | 推理 | 客户端总耗时 |
| --- | --- | ---: | ---: | ---: |
| 首次加载，中文提示词，seed=42 | 1024×1024 PNG | 8.266 秒 | 2.992 秒 | 13.150 秒 |
| 模型已加载，英文提示词，seed=123 | 1024×1024 PNG | 0.002 秒 | 2.231 秒 | 3.389 秒 |
| 后台提交，断开后重新连接取结果，seed=17 | 1536×864 PNG | — | 3.345 秒 | 未计入轮询耗时 |

这些是单次烟测记录，不是统计性能基准。客户端总耗时包含握手、工具调用、输出保存和下载；
推理时间包含提示词编码、采样和 VAE 解码。其它 GPU 负载、首次运行和尺寸会影响耗时。

- 真实采样阶段收到了逐步进度，默认 9 steps 在该 Diffusers 版本中回报 9 次回调。
- 服务重启后，先前完成的 PNG、任务状态和结果链接仍可读取。
- 接口简化后，客户端仅传提示词和宽高，已重新生成并校验 1024×1024 PNG；
  返回记录中的种子由服务端生成，采样步数为 9。
- 非法宽度 257 通过 MCP 返回工具错误。
- 20-step 真实任务在采样中被取消，最终状态 `canceled`，没有发布生成结果。
- 取消之后再次真实生成成功，工作循环可继续使用。
- 服务由独立 systemd 用户 unit 管理，配置了开机启动和已启用的用户 linger。

原始测试图片和包含完整任务/进度/下载信息的 JSON 放在部署者的 `artifacts/` 目录，
不包含在公开源码包中。具体服务器地址和目录记录在被 Git 忽略的 `LOCAL_VALIDATION.md`。

- CPU offload 提供配置入口，但本次 GPU 验证使用 `false`。
- 运行配置为可信局域网单租户；没有进行公网代理、OAuth 或多用户隔离测试。
